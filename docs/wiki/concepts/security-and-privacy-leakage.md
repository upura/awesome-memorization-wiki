# セキュリティと情報漏洩

## 定義

言語モデルの訓練データ暗記が**個人情報や機密情報の漏洩**に繋がる問題
（[Ishihara 26](../papers/ishihara-2026-memorization-survey.md) 6·1）。
特にドメイン特化のコーパスで訓練された場合 [Jagannatha 21, Singhal 23, Yang 22]、
漏洩の影響が深刻である。

法律や報道分野では「**忘れられる権利**」に関する議論も進んでいる
[Garg 20, Ginart 19, Henderson 22, Li 18]。この観点は EU 一般データ保護規則（GDPR）を
はじめとするデータ保護法とも関係が深く、**今後の研究と制度設計が求められる領域**である。

## 訓練データ抽出の手続き（2 段階）

[Carlini 21](../papers/carlini-2021-extracting-training-data.md) が確立した構造。

1. **候補生成**: 訓練データの候補となるテキストを大量に生成する
2. **[メンバーシップ推論](membership-inference.md)**: 生成された候補が訓練セットに含まれるかを判定する

### 候補生成の詳細

- プロンプトは特殊トークンのみを起点とする研究もあるが、
  学習に用いられたと考えられるデータセットから実際にテキストを抽出して活用する場合も多い
- 明示的に公開されていなくても「Bob's phone number is」や「Alice's password is」といった
  **推察も可能である** [Carlini 19, Henderson 18]
- 動的にプロンプトを変化させる研究も存在する [Kassem 25, Wang 24b]

### デコーディング手法の影響（対立あり）

| 報告 | 内容 |
|---|---|
| [Carlini 23b](../papers/carlini-2023-quantifying-memorization.md) | デコーディング戦略の違いは実験結果に**大きな影響を与えない** |
| [Lee 23] | top-k や top-p サンプリングの方が訓練データを**より多く抽出する**傾向 |
| [Hayes 25] | サンプリングによる**確率的な揺らぎ**を考慮した議論の重要性を強調 |

## データポイズニング

悪意のあるデータや誤解を招くデータを訓練セットに**意図的に混入させる**手法
[Carlini 24]。暗記は誤情報の再生産にもつながる。懸念されている手口:

- クローリング対象のうち**ドメイン切れの URL を購入**し悪意のあるデータを配置する
- Wikipedia の記事を書き換えて誤情報を注入する
- 特定の入力に対してモデル開発者が意図しない挙動を引き起こす**バックドア** [Wang 25b]

## 主要な論文

- [Carlini 21](../papers/carlini-2021-extracting-training-data.md) — GPT-2 から個人情報が抽出できると示した原典。
  1,800 候補のうち **600 件超**が訓練データの逐語コピー（最良構成で精度 67%）。
  抽出例には個人の氏名・住所・メール・電話・FAX 番号が含まれる。
  ただし**狙い撃ちではなく無差別抽出**であり、論文自身が
  「実際の敵対者が特定ユーザを狙うために運用できる攻撃を作ることが目的ではない」と明言している
- [Carlini 24] — Web スケールの訓練データセットへのポイズニングは実用的である
- [Jagannatha 21] — 臨床コーパスで、**希少疾患を持つ患者が高い漏洩リスク**に晒される
- [Hayes 25] — 確率的抽出による暗記の測定
- [Wang 25b] — 暗記の観点から見たバックドア防御

## 横断的知見

**「暗記の測定」と「攻撃」は同じ手続きである。** 訓練データ抽出は
候補生成 + [メンバーシップ推論](membership-inference.md) の 2 段階であり、これは
[文字列類似度による定量化](string-similarity-memorization.md)（サーベイ図2）と
[メンバーシップ推論による定量化](membership-inference.md)（図3）の合成にほかならない。
研究の測定器と攻撃者のツールは区別できない。
だからこそサーベイ 7·1 節は「**どのような状況を想定した研究なのかを明確にした上で、
適切な実験設定を選ばなければならない**」と述べる。→ [評価の枠組み](evaluation-framework.md)

**セキュリティの観点では、文字列一致そのものは本質ではない。**
サーベイ 7·1 節の重要な区別。セキュリティでは
**個人情報や機密情報が漏洩するか否かが本質的な問題**であり、
許容可能な暗記と深刻度の高い暗記を区別する必要がある。
[Lee 20] は既存研究の多くがこの区別をしていないと指摘した。
対照的に[著作権](copyright.md)の観点では、文字列の表層的な一致に注目するのが
合理的な場合もある。**同じ「暗記率 30%」でも、セキュリティと著作権では意味が違う。**

**低頻度データほど危険という逆説。** [Jagannatha 21] は臨床コーパスで
希少疾患を持つ患者が高い漏洩リスクに晒されると実証した。
[Satvaty 25](../papers/satvaty-2025-language-sensitive.md) も低資源言語ほどメンバーシップ推論の性能が高まると報告する。
一方 [文字列の重複](string-duplication.md) は「重複が多いほど暗記されやすい」と述べる。
これは矛盾ではなく**測っているものが違う**——重複が多い文字列は暗記されやすいが、
重複が少ない**外れ値的なデータほど識別しやすい**（メンバーシップ推論の観点）。
そして守るべき個人情報はまさに外れ値の側にある。
**[重複排除](deduplication.md)は、最も守るべきデータには効かない。**

**デコーディング手法の影響については対立が未解決である。**
[Carlini 23b](../papers/carlini-2023-quantifying-memorization.md) と [Lee 23] の報告は食い違っており、
サーベイはどちらかを採用せず両論を併記している。この Wiki でも消さない。

## 未解決の問い

- デコーディング戦略の影響に関する [Carlini 23b](../papers/carlini-2023-quantifying-memorization.md) と
  [Lee 23] の対立は、モデル規模・ドメイン・暗記の定義のどの差から生じるか
- 「許容可能な暗記」と「深刻度の高い暗記」の操作的な区別 → [暗記](memorization.md)
- 忘れられる権利への技術的対応は [逆学習](machine-unlearning.md) で十分か。
  削除の完了をどう検証するか（[反実仮想に基づく定義](counterfactual-memorization.md) の測定困難と同じ壁）
- 外れ値的な機密データを守る手法は何か。重複排除も差分プライバシ（粒度問題）も効きにくい
- データポイズニングの検出は暗記の定量化手法で可能か [Wang 25b]
