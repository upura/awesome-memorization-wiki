# lint

Wiki は放っておくと腐る。定期的に走らせる（目安: ingest 5 本ごと）。
**検出した問題を勝手に全部直さない。** 判断が要るものは人間に出す。

## チェック項目

### A. 構造（自動で直してよい）

1. **壊れたリンク** — 相対リンクの参照先ファイルが無い。
   - 概念ページの `## 未解決の問い` に出てくるものは**意図的なマーカー**なので残す。
   - それ以外は、ページを作るか、リンクを外す。
2. **片方向リンク** — 概念 → 論文 のリンクがあるのに、論文ページの
   `## Wiki 内の接点` から返っていない（またはその逆）。返リンクを足す。
3. **必須セクション欠落** — `CLAUDE.md` 6 節の見出しが無いページ。
4. **Frontmatter 違反** — 必須キー欠落、`axis` の値が
   訓練セット / モデル / 出力 / 横断 のいずれでもない、など。
5. **README.md 目次の同期ズレ** — `docs/wiki/**/*.md` の実体と目次の行が一致しない。
6. **命名規約違反** — ファイル名が `CLAUDE.md` 3 節の規約に合わない。
7. **Obsidian の `[[wikilink]]` の残存** — Jekyll が解決できず公開サイトでリンク切れになる。
   `CLAUDE.md` 5 節の相対リンクに書き換える。
8. **リスト項目内の未エスケープパイプ** — kramdown が表として誤解釈する。`\|` にする。

### B. 内容（人間に報告する。勝手に直さない）

9. **孤立ページ** — どこからもリンクされていない。なぜ孤立したかが情報である。
10. **根拠 1 本の概念ページ** — `## 主要な論文` に論文が 1 本しかない。
   概念として早すぎる可能性がある。統合先の候補を提案する。
11. **矛盾** — 同じ事象について異なる記述をしている 2 ページ。
   **どちらかを消さない。** 両ページの `## 横断的知見` に対立として明示したうえで、
   `docs/wiki/conflicts.md`（対立の台帳）に項目を追加する。
   台帳には「切り分けられていない交絡」と「決着させる実験」を必ず書く。
   （例: 文脈長の効果が英語と日本語で逆 →
   `concepts/context-length.md` と `concepts/multilingual-and-domain.md` の間の対立は、
   消してはならない知見である）
12. **空の横断的知見** — `## 横断的知見` が空、または 1 本の論文の要約でしかない。
    これは「繋げ損ねている」サイン。最も重要な検出項目である。
13. **stub の滞留** — `stub: true` のまま長く放置されている論文ページを列挙する。
14. **解決済みの問い** — `## 未解決の問い` に、その後の ingest で答えが出たものが
    残っていないか。答えが出たら消さずに「→ 答えた論文へのリンク」を追記する。
15. **`questions.md` の同期ズレ** — 概念ページの `## 未解決の問い` の増減が
    `docs/wiki/questions.md`（研究アジェンダ）に反映されているか。
    分類（A 文献調査で閉じうる / B 実験が要る / C 枠組みの問題）も見直す。

## 実行

A の機械的な検査は `tools/verify_wiki.py` が担う。まずこれを走らせる。

```sh
python3 tools/verify_wiki.py
```

B は人間の判断が要るので、Wiki を読んで報告する。

## 出力

```
## 自動修正した項目
- ...

## 判断が必要な項目
### 矛盾
- ページ A と ページ B: ...

### 繋がりが薄いページ
- ページ C: 横断的知見が実質空

## 知識ギャップ（次に ingest すべき方向）
- ...
```

最後に `log.md` へ 1 行追記する:

```
| 2026-07-29 16:00 | lint | verify_wiki.py 通過。Fixed 3 broken links, flagged 2 conflicts, 1 orphan |
```
