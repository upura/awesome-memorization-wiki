# ingest-paper

論文 1 本を Wiki に取り込む。**1 本の ingest で 10〜15 ページに更新が波及するのが正常**。
サマリーを 1 枚書いて終わりなら、繋げ方を間違えている。

## 手順

### 0. 取り込み

- 引数が URL なら PDF を `docs/raw/papers/{筆頭著者姓}-{年}-{スラッグ}.pdf` に保存する。
  J-Stage / arXiv などは `curl -L` で取得できる。
- **日本語 PDF は `pdftotext -enc UTF-8` を使う**。Python の pypdf は CID フォントで
  文字化けする（このリポジトリの軸論文で実証済み）。poppler が無ければ `brew install poppler`。
- 長い PDF は章ごとにページ範囲を切って読む。

### 1. 読む

要約する前に全文を読む。特に **図表のキャプション**と**関連研究の節**を落とさない。
関連研究の節は、既存の Wiki ページとの接続点が最も濃い場所である。

### 2. サマリーページを書く

`docs/wiki/papers/{規約に沿った名前}.md` に、`CLAUDE.md` の Frontmatter と
必須セクション（TL;DR / 位置づけ / 手法・実験 / 主要な知見 / 限界・批判 / Wiki 内の接点）で書く。

- `axis` には サーベイ図1 の 3 軸（訓練セット / モデル / 出力）のどれに属するかを書く。
- サーベイ本文に引用キーがあれば `citekey` に必ず入れる。
- **原論文を読んでいない場合**は frontmatter に `stub: true` と
  `source_note: サーベイ [Ishihara 26] 経由（原論文未読）` を書く。嘘をつかない。

### 3. 概念を抽出する（ここが本体）

論文から 3〜7 個の主要概念を抽出し、それぞれについて:

- 既存の概念ページがあれば、`## 主要な論文` に 1 行追加し、
  **`## 横断的知見` を更新する**。ここが最も重要な作業である。
  「この論文単独で言えること」は書かない。**既存ページの記述と突き合わせて
  初めて言えること**だけを書く。たとえば:
  - 「A は X と報告したが、本論文は Y を観測しており、条件 Z が効いている可能性がある」
  - 「A・B・C がいずれも同じ傾向を報告しており、英語では再現性が高いと言える」
- 既存ページが無ければ新規作成する。ただし**根拠が 1 本しかない概念はページにしない**
  （`verify_wiki.py` が検出する）。
  代わりに近い既存概念ページの `## 未解決の問い` に候補として書き留める。
- `## 未解決の問い` を見直す。この論文が答えた問いは「→ この論文へのリンク が部分的に回答」
  と追記して残す（消さない）。新たに生じた問いを足す。

### 4. 双方向リンクを張る

概念ページから論文ページへリンクしたら、論文ページの `## Wiki 内の接点` からも
その概念ページへリンクを返す。片方向リンクは `lint` で検出される。

### 5. `questions.md` と `conflicts.md` を更新

- 答えた問いには `→ 論文へのリンク` を追記する。**問いは消さない**
- 新たに立った問いを `docs/wiki/questions.md` の該当分類に足す
- 既存の記述と矛盾したら `docs/wiki/conflicts.md` に項目を追加する

### 6. `README.md` の目次を更新

該当セクションに 1 行追加（`README.md` がサイトのトップページ 兼 カタログを兼ねる）。
掲載漏れは `python3 tools/verify_wiki.py` が検出する。

### 7. `log.md` に追記

`docs/wiki/log.md` の末尾に 1 行、**追記のみ**。リンクは `log.md` からの相対パスで書く:

```
| 2026-07-29 14:32 | ingest-paper | Added [Carlini 23b](papers/carlini-2023-quantifying-memorization.md), updated [文字列の重複](concepts/string-duplication.md) [モデルサイズ](concepts/model-size.md) |
```

### 8. 検証

```sh
python3 tools/verify_wiki.py
```

リンク切れ・必須セクション欠落・片方向リンク・目次の掲載漏れを検出する。
**通してから終了する。** CI（`.github/workflows/lint.yml`）でも走る。

## 終了時の報告

人間に対して次を報告する:

1. 新規作成したページ / 更新したページの一覧
2. **既存の記述と矛盾した点**（あれば。無ければ「なし」と明記）
3. 新たに立った未解決の問い
