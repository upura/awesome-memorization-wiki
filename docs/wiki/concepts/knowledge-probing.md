# 知識を問うタスクによる暗記の定量化

## 定義

特定の知識を問うタスクを通じて言語モデルの暗記を定量化する方法
（[Ishihara 26](../papers/ishihara-2026-memorization-survey.md) 3·2§3）。

[文字列の類似度](string-similarity-memorization.md)や [メンバーシップ推論](membership-inference.md) が
「訓練データそのもの」との関係を測るのに対し、この系統は
**モデルが持っている知識を下流タスクで引き出して測る**。

## 主要な論文

- [Chang 23](../papers/chang-2023-speak-memory.md) — 訓練データの一部が欠損した入力に対し、モデルが欠損部分を復元できるかを測定（ChatGPT / GPT-4 が知っている書籍の「考古学」）
- [Xie 24a] — 論理的な思考が必要な問題（knights and knaves パズル）を用い、暗記による性能の変化を調査
- [Chang 25] — 知識獲得の深さを 3 段階で計測: 文字列一致で測る暗記、表現を言い換えられる**意味的汎化**、複数の知識を組み合わせて回答できる**構成的汎化**
- [Hong 25b], [Zhang 24] — 暗記と汎化の違いを問う研究

## 横断的知見

**この定義だけが、事後学習済みの実用モデルに適用できる。** サーベイは 3〜5 章で
原則としてベースモデルを扱うが、[Chang 23](../papers/chang-2023-speak-memory.md) は ChatGPT や GPT-4 という
**事後学習を施したモデル**を対象にでき、暗記度合いが Web 上の出現頻度と関連していると報告した。
理由は明快で、この手法は生成確率へのアクセスも訓練セットの知識も必要とせず、
API 越しの入出力だけで成立するからである。
[メンバーシップ推論](membership-inference.md) の多くの手法が対数尤度を要求するのと対照的である。
**閉じたモデルを調べる唯一の現実的な窓**という位置づけ。

**同時に、[評価の正当性](data-contamination.md)の問題と不可分である。** 知識を問うタスクで
高い性能が出たとき、それが汎化なのか、そのベンチマークを暗記しているだけなのかは
原理的に区別できない。つまりこの手法は暗記の**測定器**であると同時に、
暗記によって**汚染される対象**でもある。[Xie 24a] が論理パズルを使うのは、
この循環を断つために「暗記しても解けないはずのタスク」を選んだと読める。

**[暗記と汎化](memorization-vs-generalization.md)の境界を段階として扱えるのは、この系統だけである。**
[Chang 25] の 3 段階（文字列一致 / 意味的汎化 / 構成的汎化）は、
暗記と汎化を二値ではなく**連続体**として測る枠組みを与えている。
文字列類似度の定義では、言い換えられた知識は「暗記していない」と判定されてしまう。

## 未解決の問い

- 「暗記しても解けないタスク」の設計は本当に可能か。[Xie 24a] のパズルも
  類題が訓練セットに含まれる可能性は排除できない
- [Chang 25] の 3 段階と、重複・[モデルサイズ](model-size.md)・[文脈長](context-length.md)の
  3 因子はどう対応するか。意味的汎化・構成的汎化もモデルサイズと対数線形に増えるのか
- 事後学習は知識を問うタスクでの測定結果をどう歪めるか。
  アラインメントによる拒否応答は「知らない」と区別できるか
- 日本語など英語以外での知識プローブは何を基準に構築すべきか → [ドメインや言語横断](multilingual-and-domain.md)
